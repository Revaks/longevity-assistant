# Ассистент долголетия

Десктопное приложение на Python/Tkinter: календарь рекомендаций, база советов
диета MIND и ассистент, отвечающий по книгам Алексея Москалева.

## Возможности

- **Календарь** — недельная сетка расписания; дни с записями дневника помечены иконкой.
- **Активность** — трекер выполнения: галочки по пунктам расписания на каждый день,
  прогресс дня и сводка по неделе.
- **Заметки** — дневник с несколькими записями на день (добавление не заменяет старые).
- **Питание** — правила диеты MIND и недельное меню, которое можно перегенерировать локальной моделью.
- **База знаний** — вкладка «Советы»: структурированные советы из всех трёх книг с поиском; вкладка «Книги»:
  поиск по полным текстам трёх книг Москалева с указанием книги и раздела.
- **Ассистент** — чат на русском: офлайн-ответы ищутся по советам и отрывкам книг
  (BM25, без сети), при запущенной Ollama модель отвечает по найденному контексту,
  а векторный поиск по отрывкам включается автоматически.

## Требования

Python 3.10 или новее и Tk. **Внешних зависимостей нет** — приложение использует только модули
стандартной библиотеки.

Tk не входит в поставку Python на большинстве систем и ставится отдельно:

| Система | Команда |
|---|---|
| Arch, Manjaro | `sudo pacman -S tk` |
| Debian, Ubuntu | `sudo apt install python3-tk` |
| Fedora | `sudo dnf install python3-tkinter` |
| macOS (Homebrew) | `brew install python-tk` |
| Windows | входит в официальный установщик с python.org |

Проверка:

```bash
python3 -c "import tkinter; print(tkinter.TkVersion)"
```

Ошибка `ImportError: libtk8.6.so: cannot open shared object file` означает ровно одно:
Python есть, а пакет Tk не установлен. Ставьте его по таблице выше.

## Запуск

```bash
python3 app.py
```

После `pip install -e .` доступна и консольная команда:

```bash
longevity-assistant
```

## Ollama — по желанию

Ассистент и генерация недельного меню работают лучше при запущенной
[Ollama](https://ollama.com), но приложение полностью функционально без неё:
ассистент ищет ответы в базе знаний, меню показывается из заготовок.

Подойдёт любая модель с возможностью `completion`:

```bash
ollama pull qwen3.5:4b
```

Для векторного поиска по книгам нужна модель эмбеддингов, например
мультиязычная `bge-m3`. Если она установлена, приложение само индексирует
отрывки в фоне и кэширует вектора в `data.db` (пересборка не нужна):

```bash
ollama pull bge-m3
```

## Книги и поиск по ним

В приложении три книги А. А. Москалева:

- «120 лет жизни — только начало»;
- «Мозг долгожителя. 7 шагов к ясности ума, крепкой памяти и устойчивому вниманию»;
- «Кишечник долгожителя. 7 принципов диеты, замедляющей старение».

Тексты нарезаны на отрывки с разделами (`longevity/data/books.json`) и ищутся
движком BM25: вкладка «База знаний» → «Книги» и офлайн-режим ассистента
работают без сети. Когда доступна модель эмбеддингов Ollama, ассистент
дополнительно использует векторный поиск: релевантные отрывки попадают
в контекст модели с указанием книги и раздела.

## Где лежат ваши данные

Заметки, отметки выполнения и настройки хранятся в SQLite-файле `data.db`:

| Система | Каталог |
|---|---|
| Linux | `$XDG_DATA_HOME/longevity-assistant` или `~/.local/share/longevity-assistant` |
| macOS | `~/Library/Application Support/longevity-assistant` |
| Windows | `%LOCALAPPDATA%\longevity-assistant` |

Если вы пользовались ранней версией, заметки из `notes.json` переносятся в базу автоматически
при первом запуске, а сам файл сохраняется под именем `notes.json.migrated` (если такая копия
уже есть, следующая получит номер: `notes.json.migrated.2`). Путь к копии записывается в базу,
в таблицу `meta` под ключом `notes_json_backup` — он найдётся и после отката на старую версию.

Если для одной даты заметка есть и в базе, и в файле, и тексты разные, ни один из них не
пропадёт: обе версии окажутся в одной заметке, перенесённая — под пометкой с датой переноса.

## Архитектура

```
app.py                              тонкая обёртка: python3 app.py -> longevity.__main__.main()
longevity/__main__.py               точка входа: собирает зависимости, обрабатывает ошибки старта
longevity/paths.py                  каталог пользовательских данных, свой на каждой платформе
longevity/content.py                загрузка JSON, датаклассы Tip/Book/Passage, проверка целостности
longevity/schedule.py               подпись времени и порядок пунктов календаря на день
longevity/search.py                 единый движок BM25F: индексы советов (SearchIndex) и книг (BookSearch)
longevity/storage.py                SQLite: заметки, отметки, настройки; кэш векторов отрывков
longevity/vectors.py                кэш эмбеддингов отрывков и поиск по косинусу (без сети)
longevity/data/*.json               советы, расписание, синонимы, MIND, метаданные + books.json (отрывки книг)
ui/app.py                           главное окно, навигация по вкладкам, восстановление состояния
ui/theme.py                         палитра, шрифты и иконки — в одном месте, а не по страницам
ui/widgets.py                       модели Ollama: список, выбор, обнаружение модели эмбеддингов
ui/rag.py                            BookRetriever: BM25 всегда + фоновая векторная индексация (Ollama)
ui/formatting.py                     оформление отрывков книг для чата и списков (без Tk)
ui/calendar_page.py                 вкладка «Календарь»
ui/activity_page.py                 вкладка «Активность» (трекер выполнения)
ui/notes_page.py                    вкладка «Заметки» (дневник)
ui/knowledge_page.py                вкладка «База знаний»: советы + поиск по книгам
ui/nutrition_page.py                вкладка «Питание»
ui/assistant_page.py                вкладка «Умный ассистент»
ui/ollama.py                        клиент Ollama: генерация и эмбеддинги
tests/                              pytest; оконные тесты пропускаются, если дисплея нет
```

Данные отделены от кода: советы и расписание лежат в JSON и правятся без изменения программы.
Пакет `longevity/` не импортирует `tkinter` — вся логика тестируется headless, интерфейс (`ui/`)
знает про пакет, обратной зависимости нет. При старте данные проверяются на целостность:
неизвестная категория, дубль идентификатора, пропущенное поле или ссылка на несуществующий
совет останавливают запуск, а не приводят к тихо неверному экрану. Останавливают с диалогом,
в котором названы и причина, и поле, — трассировки в консоль, которой под `pythonw` или в
macOS-бандле просто нет, для этого недостаточно.

## Разработка

```bash
pip install -e ".[dev]"
pytest
```

Набор тестов проходит и без дисплея: те, что создают окно, в этом случае
пропускаются (`env -u DISPLAY pytest` — зелёный, с пропусками). Логика пакета
`longevity/` проверяется целиком в любом случае — она про Tk не знает.

## Дисклеймер

не заменяет консультацию врача. Лекарства и добавки — только по назначению специалиста.
